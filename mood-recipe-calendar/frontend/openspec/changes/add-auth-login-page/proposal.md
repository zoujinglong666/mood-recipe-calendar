## Why

当前登录入口分散在“我的”页卡片中；当接口返回业务码 401 时，请求层只清除本地会话并让原页面报错，用户不知道应在哪里恢复登录，也无法回到原本想访问的功能。

## What Changes

- 新增独立登录页，沿用锅仔 IP、现有主题 token、深浅色模式与微信小程序登录能力。
- 请求层识别 HTTP 401 或业务码 `code: 401` 后只执行一次会话失效处理，并跳转登录页；保留用户原本要访问的页面作为登录后的回跳目标。
- 登录页在微信小程序中使用现有微信登录流程；H5 明确展示当前无法使用微信授权的说明与返回入口。
- 登录成功后恢复目标页面；取消、失败和重复 401 均提供明确且不循环跳转的恢复路径。

## Capabilities

### New Capabilities

- `auth-login-recovery`: 为登录失效提供独立登录页、统一 401 恢复与登录后回跳。

### Modified Capabilities

- 无。

## Impact

- 前端：新增登录路由与页面；调整 `src/api/request.ts`、登录工具和全局会话失效事件处理。
- 后端：不新增接口，复用现有 `/api/auth/login` 登录契约与服务端 Token 鉴权。
- 兼容性：微信小程序调起 `uni.login`；H5 不伪造微信授权，提供清晰降级说明。
- 不新增依赖，不在客户端保存 AppSecret、openid 或 Token 以外的敏感凭据。
