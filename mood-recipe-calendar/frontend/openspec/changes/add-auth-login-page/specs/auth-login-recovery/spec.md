## Purpose

为会话失效的用户提供清晰、可恢复且跨端一致的登录入口，避免业务页面在 Token 过期后停留在错误或半登录状态。

## ADDED Requirements

### Requirement: 用户可以在独立登录页恢复会话

系统 SHALL 提供独立登录页，明确说明登录用途并展示锅仔品牌视觉。微信小程序 MUST 调用已存在的微信登录能力；H5 MUST 明确说明当前无法使用微信授权，且提供返回入口。

#### Scenario: 微信小程序用户主动登录

- **WHEN** 未登录用户在登录页点击微信登录
- **THEN** 系统完成微信授权登录并显示进行中、成功或可恢复的失败状态

#### Scenario: H5 用户访问登录页

- **WHEN** 用户从 H5 进入登录页
- **THEN** 系统不伪造微信授权，展示平台限制说明与返回操作

### Requirement: 会话失效会统一进入登录恢复流程

系统 MUST 在接口 HTTP 状态码为 401 或业务响应 `code` 为 401 时清除本地会话并跳转独立登录页。系统 SHALL 记录首次失效时的可访问目标，以便登录成功后恢复该目标，并 MUST 防止并发失败请求造成重复跳转或重定向循环。

#### Scenario: 业务码 401

- **WHEN** 接口返回 `{ "code": 401, "message": "登录已过期，请重新登录" }`
- **THEN** 系统清除旧登录信息并进入登录页，而不是仅在原业务页面显示请求错误

#### Scenario: 登录后回到原功能

- **WHEN** 用户因 401 被引导登录且登录成功
- **THEN** 系统回到首次失效前要访问的页面；没有可安全恢复的目标时回到“我的”页

#### Scenario: 同时发生多个 401

- **WHEN** 多个接口在同一时刻返回 401
- **THEN** 系统只启动一次登录跳转，且不会出现多层登录页面或重复提示
