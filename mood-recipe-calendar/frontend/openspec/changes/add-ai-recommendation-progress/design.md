## Context

参见 `proposal.md` 的 Why。当前 `GET /api/recipes/recommend` 在一个同步请求中依次读取偏好、调用 Agnes 文本模型、调用 Agnes 图像模型并回退本地菜谱；前端只能知道请求是否结束。微信小程序不应依赖浏览器专属的 SSE，且进度必须对应真实后端节点而不是前端计时器。

## Goals / Non-Goals

**Goals:**

- 用最小的任务协议暴露真实阶段，同时保留现有同步接口兼容旧客户端。
- 让文本结果与图片结果独立判定，图片失败只触发视觉降级。
- 让任务只对创建者可见，并限制客户端轮询与服务端临时状态寿命。
- 让等待动效表达“状态指示”，不抢占菜谱内容层级。

**Non-Goals:**

- 不暴露思维链、原始提示词、供应商响应或内部异常堆栈。
- 不建设通用任务平台、消息队列、Redis 状态机或可恢复的长期作业。
- 不改动付费私人菜单和虚拟支付扣权益流程。

## Decisions

### 1. 创建任务加短轮询，不使用 SSE 或 WebSocket

新增创建任务和读取任务状态两个接口。前端创建后每约 900ms 查询一次，终态、离页或 90 秒上限到达即停止。短轮询可直接复用现有 `uni.request`，在 H5 和微信小程序中行为一致；相比 SSE/WebSocket，无需新增连接管理和跨端适配。

任务响应包含 `jobId`、总体状态、当前阶段、阶段列表、用户可读说明、回退标记和可选菜谱结果。阶段值固定为读取记忆、文本生成、图片生成、整理结果和本地回退；前端只渲染服务端返回状态。

### 2. 临时任务使用进程内存和 Java 虚拟线程

后端使用带所有者 `openid` 的短期任务对象与并发 Map，生成工作提交到 Java 21 虚拟线程执行器。完成任务保留十分钟并在创建或查询时惰性清理。推荐任务是短期、可安全重试的交互状态，当前单实例阶段无需数据库表或 Redis。

这是有意的最小实现：多实例部署或要求重启后恢复任务时，再将任务状态迁移到共享存储。

### 3. AI 服务通过阶段回调报告真实边界

推荐编排在读取偏好前标记“读取记忆”；文本请求发出前标记“生成菜谱”；获得合法菜谱后、图像请求发出前标记“制作封面”；最终装配与记录曝光时标记“整理结果”。回调只发生在真实动作开始或完成时，不根据经过时间推进。

文本生成与封面生成从当前单体方法中拆出最小可复用边界。同步旧接口仍调用同一编排逻辑，避免两套推荐规则漂移。

### 4. 失败分为封面降级、本地回退和整体失败

文本成功而图片失败时，任务仍成功并在图片阶段返回“封面暂时未生成”；前端沿用锅仔占位图。文本失败时执行现有去重、忌口和偏好加权的数据库回退，阶段明确标记“已切换本地推荐”。只有 AI 和本地候选都不可用时任务失败。

不向客户端返回供应商原始错误；详细失败继续写入现有运营事件，客户端只收到可行动文案。

### 5. 进度 UI 使用现有页面、素材和 CSS 动画

当前静态骨架替换为锅仔思考卡：当前步骤有状态指示，完成步骤显示勾选，未开始步骤保持低强调。持续动效仅作用于锅仔和当前状态点，使用 `transform/opacity`；步骤切换使用 180ms 强 `ease-out` 过渡。完成后轨迹折叠成次级“锅仔这次做了什么”，菜品仍是首屏主角。

`prefers-reduced-motion: reduce` 下移除持续位移和缩放，仅保留不超过 180ms 的透明度反馈。所有可操作区域保持至少 88rpx。

## Risks / Trade-offs

- [进程重启会丢失进行中的任务] → 客户端在查询不到任务时停止轮询并允许重新推荐；需要多实例时再引入共享存储。
- [短轮询增加少量请求] → 采用约 900ms 间隔、90 秒硬上限和终态立即停止，不后台轮询。
- [用户快速重复点击创建多个任务] → 前端创建中禁用操作，服务端按用户复用尚未结束的同类任务或拒绝重复创建。
- [旧同步接口与新任务规则漂移] → 两个入口复用同一推荐编排服务。
- [图片服务慢于文本服务] → 清楚标记当前处于封面生成；图片失败后立即以占位图完成，不重复阻塞。
- [任务 ID 被猜测] → 使用不可预测 UUID，并在每次查询时核对认证 `openid`，不返回他人任务是否存在。

## Migration Plan

1. 在 AI 菜谱服务中拆出文本与封面阶段，并保留同步调用兼容层。
2. 新增短期推荐任务服务、创建接口和查询接口，接入现有偏好、回退与运营事件。
3. 前端增加任务 DTO、创建和查询方法，将推荐页加载态接入真实阶段轮询。
4. 完成终态折叠轨迹、封面降级、错误重试、离页清理和减少动态效果样式。
5. 运行后端单元测试、前端 lint/类型检查、H5 与微信小程序构建，并用可控桩验证各阶段。

回滚时前端恢复调用同步推荐接口，新任务接口可以保留供新版本使用；无持久数据迁移。
