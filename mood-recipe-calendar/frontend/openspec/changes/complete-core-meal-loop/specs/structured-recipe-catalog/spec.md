## Purpose

保证任何干净环境和已有旧数据的环境都拥有足够丰富、结构完整且真实可执行的基础菜谱，为 AI 降级和个性化推荐提供可靠底座。

## ADDED Requirements

### Requirement: 内置菜谱不少于 200 道
系统 SHALL 随应用发布至少 200 道名称唯一的结构化菜谱，每道包含真实菜名、菜系或风味标签、适用心情、预计时长、难度、简介、图片、具体食材清单和有顺序的做法步骤。

#### Scenario: 干净数据库首次启动
- **WHEN** 应用连接空数据库完成初始化
- **THEN** 可用于推荐的唯一菜谱数量不少于 200

### Requirement: 菜谱内容可直接执行
每道内置菜谱 MUST 至少包含两项有名称和用量的具体食材及三个清晰步骤，不得使用“主料”“配菜”“适量食材”等占位名称，也不得让图片提示词把原材料摆盘当成成品菜。

#### Scenario: 自动质量校验
- **WHEN** 运行菜谱目录校验
- **THEN** 系统验证数量、名称唯一性、字段完整性、食材具体性、步骤数量、时长范围及 JSON 可解析性，任一不合格即失败

### Requirement: 旧库升级幂等且不破坏关联
系统 SHALL 按稳定菜名补齐缺失菜谱并修复内置占位内容，多次启动不得产生重复项，也不得清空、重建或改变已被曝光、反馈和记录引用的菜谱主键。

#### Scenario: 从现有 117 道目录升级
- **WHEN** 已有数据库启动包含新版目录的应用
- **THEN** 系统补齐到至少 200 道并更新匹配的内置占位内容，既有用户记录和反馈仍能访问原菜谱

#### Scenario: 重复启动
- **WHEN** 同一数据库再次执行目录初始化
- **THEN** 菜谱数量和稳定标识不因重复初始化继续增长
