## Why

现在的做菜模式只是展示静态步骤和计时器，无法判断用户卡在哪里、解释火候与成熟标志，也没有利用已积累的口味、家庭情况和做菜反馈。需要将它升级为有可追溯知识、能因人施教、能在烹饪现场持续对话的锅仔做菜智能体。

## What Changes

- 新增烹饪知识库与 RAG 检索链路，知识块包含技法、食品安全、火候、失败补救、替代食材、适用场景和来源信息。
- 做菜智能体在回答前同时读取当前菜谱、当前步骤、用户长期记忆、做菜结果反馈和检索证据，再生成可执行指导。
- 将简略菜谱扩展成完整教学版：备料、步骤目标、操作、火力、时间、成熟判断、常见失败和补救方法。
- 做菜页增加真实对话入口、快捷提问、证据来源、加载/重试/降级状态，并保留现有单步聚焦、计时和进度恢复能力。
- 将“太难、没做成、某步反复提问”转化为可解释的熟练度与教学偏好，下次自动调整解释细致程度。
- 模型或检索不可用时，必须显式降级为原菜谱步骤和安全提示，不得伪造引用或假装已检索。

### 目标

- 用户可以在任意步骤追问“怎样算熟”、“火大了怎么补救”、“没有这种食材怎么换”，并得到结合当前菜谱的回答。
- 回答中能看到实际检索到的知识条目，且不会引用未检索的来源。
- 同一道菜对新手给出更细的判断与补救，对熟练用户保持简洁。

### 非目标

- 本变更不进行大模型参数微调；首版使用可审计 RAG 和用户记忆，为后续评估是否需要微调积累数据。
- 不替代专业厨师认证、医疗或特殊人群临床营养建议。
- 不在首版引入独立向量数据库；先在现有 MySQL 内完成可替换的检索层，数据规模或检索质量不足时再升级。

### 验收标准

- 一道菜能生成完整教学指南，每步至少有操作、火力/时间、成功标志和失败补救。
- 提问返回回答、当前步骤建议、检索来源以及是否降级，并通过服务端安全校验。
- 关闭个性化后不读取烹饪熟练度与历史反馈；开启后能说明使用了哪些记忆。
- H5 和微信小程序都可文字提问；计时、进度恢复和失败重试行为一致。

## Capabilities

### New Capabilities

- `rag-cooking-coach`: 覆盖烹饪知识检索、完整教学指南、分步对话辅导、个性化教学与可追溯降级。

### Modified Capabilities

无。

## Impact

- 后端：新增烹饪知识数据、检索服务、做菜智能体和对话 API；复用现有 `LlmClient`、`AgentMemoryStore`、菜谱安全规则和内容安全检查。
- 数据库：新增知识块表及最小的用户烹饪学习事件，保留来源、版本和审核时间。
- 前端：扩展 `src/pages/cooking/index.vue`、新增 cooking-agent API 类型与加载/错误/降级交互；不新增独立页面。
- 跨端：H5 与微信小程序使用同一 HTTP API；首版不引入语音识别。
- 依赖：首版不增加新运行时依赖，检索层保持可替换，便于以后接入 embedding/向量数据库。
