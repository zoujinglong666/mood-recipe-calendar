## Context

参见 `proposal.md` 的 Why。当前“我的”页内联承担头像和昵称编辑，设置图标却指向隐私政策；“关于我们”直接绑定现有主题组合式函数并渲染完整外观设置。用户状态、退出接口、主题状态和上传能力均已存在，因此本次是页面职责迁移与交互闭环，不需要新增后端协议或状态体系。

另一个约束是多个业务页面会在显示时调用自动登录。如果退出后立即跳到首页或“我的”页，会立刻创建新会话，削弱退出反馈。因此退出成功后保持在不会自动登录的设置页，并呈现未登录状态；只有用户随后主动进入需要身份的业务流程时才沿用既有登录机制。

## Goals / Non-Goals

**Goals:**

- 用一个页面承接账号资料、主题偏好和退出操作，并复用现有状态与接口。
- 让主题模式成为三选一的清晰模型，避免“深色模式”和“跟随系统”两个开关形成冲突状态。
- 保证资料和会话变更只有一个提交入口，且所有异步操作均有加载、成功、失败和重试反馈。
- 在微信小程序与 H5 中保持相同的信息架构与结果。

**Non-Goals:**

- 不修改后端用户或会话协议，也不实现账号注销。
- 不引入新的全局状态、UI 库、动画库或主题抽象。
- 不把资料编辑组件过早抽成通用组件；当前仅设置页使用。

## Decisions

### 1. 新增设置页，现有页面做职责迁移

新增 `src/pages/settings/index.vue`，通过 `definePage` 注册 `settings` 路由。“我的”页设置按钮改为导航到该路由，移除其内联头像和昵称编辑逻辑，仅展示用户身份，并允许点击资料区进入设置。“关于我们”删除主题组合式函数绑定、外观设置模板和对应样式。

备选方案是把设置做成弹窗或继续扩充“我的”页，但这会保留入口语义混乱，也不利于后续增加账号权利入口，因此不采用。

### 2. 复用用户 Store 和现有资料接口

设置页直接读取现有用户 Store；进入页面时仅从缓存恢复会话并按需刷新资料，不主动调用自动登录。昵称更新沿用用户更新接口，头像沿用现有文件上传后更新资料的两步流程。成功后刷新 Store，使“我的”页自然同步。

微信小程序继续使用平台头像选择和昵称输入能力；H5 使用普通文件选择/上传和文本输入作为等价降级。若当前构建能力无法安全提供 H5 头像文件选择，本次至少保证头像展示与昵称编辑可用，并将头像操作明确标记为当前端不可用，而不是展示无效按钮。

备选方案是复制一份局部用户对象并在返回时同步，但会产生双状态和陈旧显示，因此不采用。

### 3. 将现有布尔主题状态映射为三态选择

设置页展示“跟随系统 / 浅色 / 深色”三个选项，行为映射如下：选择跟随系统调用现有跟随系统动作；选择浅色或深色时先关闭跟随系统，再调用现有主题切换动作。主题色继续调用现有选择动作。页面只消费现有组合式函数，不修改主题持久化协议。

备选方案是原样迁移两个开关，但“跟随系统开启同时深色开关关闭”等组合难以解释，三态选择更符合用户心智且不需要新数据结构。

### 4. 服务端成功后才清理本地会话

退出按钮置于页面底部危险操作区。用户确认后锁定按钮并调用既有退出接口；成功后调用 Store 的退出动作并保持当前页，失败则保留 Store 与缓存。这样避免网络抖动导致客户端误以为已退出，同时也避免跳转到会自动登录的页面。

不采用“无论接口结果都清本地”的方案，因为服务端会话可能仍有效，且不符合失败可恢复要求。

### 5. 使用现有视觉令牌做克制的锅仔延展

页面采用自定义导航、分组卡片、足够大的行级触控区域和底部安全区。锅仔只出现在顶部身份卡或一句短提示中，用于建立陪伴感，不重复堆叠大插画。所有颜色使用现有主题变量；危险按钮保留独立红色语义，并为选中、加载、禁用和按压提供可识别状态。

## Risks / Trade-offs

- [退出后进入任意需身份页面会按现有机制重新登录] → 设置页停留在明确未登录状态；不在本变更扩大为全局“禁止自动登录”状态，以免破坏现有核心流程。
- [资料编辑从“我的”页迁移会改变熟悉路径] → 资料展示区可点击进入设置，右上角设置入口也保持明显，减少查找成本。
- [H5 与微信头像选择能力不同] → 使用条件编译提供端侧实现；不可用时给出明确状态，不渲染假交互。
- [主题三态映射到两个既有状态可能出现初始化短暂不一致] → 展示值由 `followSystem` 优先计算，否则读取当前主题，所有写入仍走原有动作。
- [退出接口慢或失败] → 按钮防重、显示进行中、失败不清理缓存并允许重试。

## Migration Plan

1. 新增设置路由与页面骨架，接入现有用户和主题状态。
2. 迁移资料编辑逻辑，并验证资料成功、失败和跨页同步。
3. 迁移外观设置，删除“关于我们”的主题逻辑与样式。
4. 改正“我的”页设置入口并精简内联编辑。
5. 接入退出确认与状态处理，验证取消、成功、失败和重复点击。
6. 执行 H5 类型检查/构建和微信小程序构建，检查浅色、深色与安全区。

回滚时恢复“我的”页资料编辑和“关于我们”外观设置，再移除设置页路由；不涉及数据迁移，现有主题与用户缓存格式保持不变。

## Verification

- 静态检查：TypeScript/Vue 检查、路由生成与未使用代码检查。
- 构建检查：H5 与微信小程序构建均通过。
- 手工流程：设置入口、返回、昵称/头像成功和失败、主题三态、主题色、关于页无主题项、退出取消/成功/失败、深色模式与安全区。
