## Why

GuozaiAgent 已接管推荐、寄语和深度推荐主链路，但当前仍可能记录敏感模型推理、返回违反用户忌口的 AI 菜谱、因脏日期中断服务，并让 AI 推荐脱离“喜欢 / 不想吃 / 做过”的学习闭环。现在需要先把安全性、权益一致性和可学习性补齐，再继续扩展工具能力。

## What Changes

- 禁止记录模型推理、提示词和用户画像正文，仅保留非敏感运行指标。
- 对普通推荐和付费深度推荐执行确定性的过敏与忌口校验，不合格时安全降级。
- 为 AI 生成推荐建立轻量曝光标识，使用户可以反馈并参与近期去重和偏好学习。
- 严格校验新记录日期，并兼容数据库中已有的非法日期。
- 保证深度推荐失败或异常时不损失用户权益。
- 让记忆快照保持只读，首页打开事件只由首页寄语入口记录，并修正时间窗口和新用户判断。
- 删除同步模型调用产生的伪“深度思考”进度和已被 Agent 替代的重复代码。
- 补充关键安全、异常与学习闭环测试。

## Capabilities

### New Capabilities

- `guozai-agent-reliability`: 规定锅仔智能体的隐私保护、忌口安全、推荐反馈、日期容错、权益一致性和真实进度行为。

### Modified Capabilities

无。

## Impact

- 后端：GuozaiAgent、GuozaiMemory、AiRecipeService、推荐/记录控制器、推荐互动持久化及测试。
- 前端：推荐结果类型与反馈请求需要支持 AI 推荐曝光标识；现有本地菜谱 ID 反馈保持兼容。
- API：推荐结果新增可选曝光标识，反馈接口兼容菜谱 ID 与曝光标识；不移除现有字段。
- 数据：新增轻量推荐曝光记录，不保存完整菜谱正文或模型推理内容。
- 依赖：不新增第三方依赖。
- 跨端：H5 与微信小程序使用同一 API 契约和反馈行为，不依赖浏览器专属能力。
- 非目标：不引入 LangChain、自治工具循环、流式模型协议或新的页面布局。
- 验收：AI 结果无法绕过忌口；失败不扣权益；非法历史日期不导致 500；AI 推荐可反馈并影响后续去重；日志不含推理与画像正文。
