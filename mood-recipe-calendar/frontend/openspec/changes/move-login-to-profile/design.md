## Context

当前“我的”身份卡始终显示设置入口和默认昵称，设置页却同时负责登录、资料和退出，导致退出后的状态语义混乱。

## Goals / Non-Goals

**Goals:** 将登录入口集中到“我的”页，复用现有登录、登出、资料刷新和状态存储能力。

**Non-Goals:** 不修改会话接口或新增账号体系。

## Decisions

- 身份卡按 `isLoggedIn` 分为两种完整视图：已登录时进入设置编辑资料，未登录时直接调用既有登录流程。
- 设置页未登录时显示简短引导并返回“我的”，避免出现第二个登录入口。
- 退出操作完成后由 store 清理本地状态；“我的”页在展示和会话过期事件后重新读取 store，避免残留资料。

## Risks / Trade-offs

- [登录过程取消或失败] → 身份卡保持未登录状态并提供可重试入口。
- [统计读取失败] → 登录仍成功展示资料，统计保留空态而不回退为未登录。

## Compatibility and Verification

- 影响两个前端页面，不增加接口或依赖。
- 验证退出、会话过期、登录成功、未登录设置访问与类型检查。
