## Context

见 `proposal.md` 的 Why。当前页面的网络流程、反馈、记录跳转、定制菜单和虚拟权益已经可用，问题集中在单页信息层级和状态表达。实现必须继续使用 uni-app 跨端能力、现有 Wot UI 导航栏、Icon 与锅仔资源，以及 `theme.scss` 中的语义令牌。

## Goals / Non-Goals

**Goals:**

- 在不改变接口的前提下，把页面重排为“推荐结论—锅仔解释—食材与步骤—完成记录”的线性任务流。
- 让 4:3 Agnes 菜品图成为视觉中心，并为无图和加载失败提供同尺寸占位，避免布局跳动。
- 明确所有可交互状态，避免重复提交、无效反馈和固定操作区遮挡内容。

**Non-Goals:**

- 不抽取新的公共页面组件；单页结构未证明会被复用。
- 不新增动效库、表单库或状态管理层。
- 不修改后端、推荐规则、权益规则或分享落地数据。

## Decisions

### 1. 使用单列沉浸式推荐卡，而非多张并列功能卡

推荐主卡从上到下包含心情标签、4:3 图片、菜名与描述、时长/难度元信息；锅仔小尺寸形象贴近对话气泡放在主卡下缘。这样生成内容与 IP 形成一个语义整体。

替代方案是保留独立锅仔 Hero 和独立菜谱卡，但会继续造成首屏空间浪费和视觉焦点竞争，因此不采用。

### 2. 主按钮随任务阶段变化

步骤收起时固定主按钮为“查看完整做法”；展开后切换为“做完了，记一笔”。步骤区标题保留“收起”作为显式次级操作。底部不再放两个等权按钮。

替代方案是同时展示“定制”和“记录”，但用户尚未查看做法时直接记录语义过早，也会削弱主路径。

### 3. 偏好反馈保持轻量，定制入口后置

“喜欢”和“换一道”放在推荐主卡之后，使用图标加文字的次级按钮；仅当菜谱有可反馈 ID 时展示。按食材定制放在正文之前的窄条入口，打开既有底部面板，权益商品仅在需要时呈现。

替代方案是继续把定制放在首屏顶部，但这会让付费能力抢占基础价值证明，不采用。

### 4. 只使用现有语义主题变量

页面表面、文字、边框和阴影全部复用 `--mrc-*` 令牌；固定底栏不再使用只适合浅色模式的硬编码背景。允许白色仅用于主色按钮上的高对比文字，遮罩使用稳定的半透明深色。

替代方案是为本页新增一组颜色变量，但当前全局令牌已经覆盖所需层级，新增变量会扩大主题维护面。

### 5. 动效只服务状态变化

保留 150–250ms 的按压反馈、步骤展开淡入和内容切换过渡；锅仔只使用现有轻呼吸效果。加载使用与最终卡片同尺寸的骨架/占位，不增加循环装饰动画，并为系统减少动态偏好提供静态表现。

### 6. 单文件完成页面重构

主要修改限定在 `src/pages/recipe/index.vue`：增加少量派生状态与图片错误状态，重写模板和 scoped 样式。现有 API、组件与资源足以完成任务，不新增公共抽象或依赖。

## Risks / Trade-offs

- [远程生成图比例或主体位置不稳定] → 使用 `aspectFill` 与固定 4:3 容器；加载失败切换到 `aspectFit` 的锅仔占位。
- [固定底栏遮挡长步骤] → 页面底部预留底栏高度与安全区之和，并在横屏/宽屏限制正文最大宽度。
- [AI 生成菜谱没有可反馈 ID] → 无 ID 时隐藏喜欢/换菜反馈区域，保留查看与记录能力。
- [定制生成耗时较长] → 提交后立即锁定按钮并显示明确进度文案，失败后恢复可编辑状态。
- [微信小程序与 H5 对部分 CSS 支持不同] → 采用 flex、grid、transform、opacity 和现有 CSS 变量，不依赖浏览器专属 API 或复杂滤镜。

## Migration Plan

1. 在单页内替换模板与 scoped 样式，保留既有事件函数和接口调用。
2. 增加防重复点击、图片失败兜底和主按钮阶段切换。
3. 依次执行类型检查、lint、H5 构建，并人工核对浅色/深色、小屏/宽屏与微信小程序安全区。
4. 若上线后出现问题，可单文件回退 `src/pages/recipe/index.vue`，无需数据库或接口迁移。

## Verification

- 静态验证：`pnpm type-check`、`pnpm lint`、`pnpm build:h5`。
- 行为验证：加载成功/失败/重试、图片失败、步骤展开/收起、喜欢/换菜处理中、定制成功/权益不足/支付处理中。
- 视觉验证：375px 等效小屏、常规手机、宽屏 H5，分别检查浅色与深色模式、安全区和无横向滚动。
