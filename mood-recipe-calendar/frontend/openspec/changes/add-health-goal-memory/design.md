## Context

现有 `UserFoodPreference` 已承载口味、菜系、忌口和辣度，前端锅仔记忆可编辑这些字段，GuozaiAgent 会把它们用于筛选、排序和 AI 提示词。本次只需在同一偏好记录中增加一个可空饮食目标。

## Goals / Non-Goals

**Goals:**

- 以一个枚举目标贯穿偏好保存、锅仔记忆展示与推荐解释。
- 给健身、减脂用户呈现可理解的健康套餐倾向，且不触碰医疗或精确营养处方。

**Non-Goals:**

- 不采集体重、身高、病史，不计算热量，也不承诺减重或增肌结果。

## Decisions

- 使用单值 `healthGoal`：`BALANCED`、`FITNESS`、`LEAN`。单选避免健康方向相互冲突；空值与 `BALANCED` 等价，保证旧数据兼容。
- 健康套餐是推荐倾向而非独立商品或订阅。复用现有菜谱文本匹配与 AI 上下文，不新增套餐表、支付或接口分支。
- 将目标写入 Agent 的本地评分、推荐理由和 AI 提示词，并在锅仔寄语中提及。过敏、忌口仍是硬过滤条件，优先级高于目标。
- 数据库迁移采用新增可空列，发布失败可回滚应用版本且不影响旧偏好读取。

## Risks / Trade-offs

- [菜谱营养元数据不足] → 首版仅按食材和烹饪关键词做温和倾向，文案不使用“治疗”“必瘦”等承诺；后续有可靠营养数据时再细化。
- [用户目标变化快] → 目标在锅仔记忆中始终可一键切换，保存后即时生效。
- [AI 忽略目标] → 本地回退排序和固定推荐理由仍读取目标，确保最小可用体验。

## Migration Plan

1. 为偏好表增加可空 `health_goal` 字段。
2. 后端将空值视为均衡饮食，前端首次读取同样显示默认选项。
3. 回滚时保留该字段但旧版本忽略它。
