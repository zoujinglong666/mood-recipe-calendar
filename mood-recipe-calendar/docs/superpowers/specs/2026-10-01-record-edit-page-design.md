# 菜谱时光机记录编辑页设计

## 目标

让用户可以从菜谱时光机的详情弹层直接编辑一条历史记录，并在独立页面完成多照片、菜名、日期、心情、时长和备注的修改。

## 方案

- 时光机详情弹层增加主操作“编辑记录”。
- 新增 `/pages/record/edit` 独立页面，使用现有记录编辑接口和上传工具。
- 编辑页提交成功后回到时光机，并让时光机重新加载数据，保证列表展示最新内容。
- 不新增后端接口；继续使用 `GET /records/{id}` 与 `PUT /records/{id}`。
- 保留现有“记录今日伙食”页作为新建记录页，避免编辑态与 Tab 导航耦合。

## 编辑页交互

1. 从详情弹层点击“编辑记录”，带 `id` 进入页面。
2. 页面加载记录详情；加载失败显示错误并返回上一页。
3. 照片区域支持追加、删除和上下移动排序，最多 9 张；保存时第一张作为封面。
4. 菜名、日期、心情、烹饪时长、备注均有明确标签；必填项在提交前就地提示。
5. 保存过程中禁用重复提交；成功后提示并回到时光机。

## 视觉与可访问性

- 复用现有 `mrc-*` 设计 token、导航栏、按钮、心情选择器和照片上传样式。
- 主按钮触摸区域不小于 44pt，所有图标按钮提供 `aria-label`。
- 底部保存栏避开安全区，滚动内容不会被遮挡。
- 所有文案统一中文，不引入新的颜色或图标依赖。

## 验证标准

- 时光机详情弹层可以打开编辑页并传递正确记录 ID。
- 编辑页可以加载并更新记录，照片排序/删除结果正确提交。
- 保存成功返回时光机后能看到更新后的菜名和照片顺序。
- 前端类型检查不新增本功能相关错误；`git diff --check` 通过。
