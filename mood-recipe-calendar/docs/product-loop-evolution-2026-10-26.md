# 晚饭主循环：产品演进构想（2026-10-26）

> 定位：这不是功能清单，是一份「把已有能力串成闭环」的路线图。
> 核心判断：锅仔的「选菜」环节已是同类产品头部水平，但用户从
> **「今晚吃什么」→「这顿饭圆满结束」** 的执行链（买—做—吃—存）断层很大。
> 本文档的所有提案，都要求挂在已有数据流上——**不为加功能而加功能**。

---

## 一、北极星：把「推荐工具」升级为「晚饭主循环引擎」

用户每天的真实旅程是：**选 → 买 → 做 → 吃 → 记 → 存 → 复盘 → 再选**。
我们目前只在「选」和「记」两端有深度，中间全程空白。而中间恰恰是：

1. **频率最高的部分**——推荐一天只用一次，买和做每天要纠缠一小时；
2. **数据最诚实的部分**——「扔掉了」「没做完」比「不喜欢吃」真实得多；
3. **竞品最难抄的部分**——选菜拼的是菜谱库和模型，执行链拼的是对一个人厨房的长期理解。

因此，此后每个功能决策都先回答一个问题：
**它让主循环的哪一段转得更顺？如果没有答案，就不做。**

```
        ┌────────────────────────────────────────────┐
        │                                            │
        ▼                                            │
   [选] 心情+时间预算+冰箱 → 推荐（带一句话理由）        │
        │                                            │
   [买] 采购清单：份量聚合 · 冰箱抵扣 · 人数缩放          │
        │                                            │
   [做] 跟做模式 · 翻车急救 · 人数即份量                 │
        │                                            │
   [吃] 做了/剩了/太难/心情 → 反馈（已有）               │
        │         └→ 剩菜改造（明晚的选择题）           │
   [存] 冰箱进出：做完自动扣减 · 拍照记录丢弃             │
        │                                            │
   [复盘] 饮食多样性观察 · 里程碑与画册（已有雏形）        │
        └─────── 更懂你（记忆系统，已有）←─────────────┘
```

---

## 二、贯穿全局的两条设计铁律

**铁律一：一次记录，多处受益。**
用户每产生一条数据（记一笔、拍一次冰箱、反馈一次"剩了"），必须在循环里至少
服务两处。做不到的入口就砍掉——这是控制功能膨胀的根本手段。

**铁律二：新入口必须挂在已有数据流上。**
下文每个提案都标注了它复用的既有模块。找不到挂靠点的提案进「不做清单」。

---

## 三、按旅程补环（每环：现状 → 断层 → 补链方案）

### 环节 1 · 选（推荐）——最强环节，补三个暗坑

**已有**：心情推荐、周计划、记忆系统、避菜、结果回流、OutputGate 质量门。

| 断层 | 补链方案 | 挂靠的既有模块 |
|---|---|---|
| 推荐不可解释 | 每道推荐附一句话理由（"你上周说想吃清淡 + 冰箱有西兰花"） | 记忆系统的证据链 + 冰箱表 + 画像快照——数据全在，缺的只是把理由生成并透出 |
| 推荐疲劳 | 「探索配额」：每周 1-2 次故意推低频菜系，配"换个新口味试试？"开关 | 菜系亲和度（学习闭环已有）+ 历史曝光记录 |
| 不感知时间预算 | 「今晚只有 20 分钟」成为一级输入，联动难度上限 | 学习闭环的难度上限（已存在，只是没暴露为快速开关） |

**串起来的关键**：这三个暗坑共用同一个「推荐理由生成器」——理由 = 记忆证据 + 冰箱联动 + 时间预算的综合解释。它不是三个功能，是一个出口。

### 环节 2 · 买（采购）——最大断层，一条食材数据流贯穿三处

**已有**：周六买菜清单订阅提醒、冰箱管理、临期提醒。

补链方案（同一个食材数据流，三个出口）：

1. **份量聚合**：三道菜都要葱花 → 合并成"葱 2 根"；**人数缩放**：家庭/独居用量差一倍。
2. **冰箱抵扣**：清单自动标注"你已有这些"——冰箱从记账本变成省钱助手。
3. **浪费追踪**：拍照记录一次丢弃 → 下周清单自动少买。这是竞品拿不到的诚实数据。

**串起来的关键**：食材表（冰箱）成为主循环的「库存账本」——推荐加分（环节 1）、
采购抵扣（环节 2）、做完扣减（环节 4）读写的都是同一张表。

### 环节 3 · 做（烹饪）——独特的种子，长成树

**已有**：cooking agent、seasoning_timing_knowledge、膳食指南 RAG、订阅消息模板。

1. **跟做模式（Cook-Along）**：分步大字 + 关键步骤提醒（"小火炖 8 分钟后叫我"）。
   做饭时手上沾着面粉没法划屏——这是厨房场景的真痛点，订阅消息模板现成。
2. **翻车急救**："盐放多了怎么办""肉柴了怎么救"——做饭时最高频最焦虑的搜索。
   现在能答「做什么菜」，答不了「做砸了怎么办」。Agent + 补救知识包即可承接。
3. **人数即份量**："三个人吃放多少盐"——人数参数贯穿烹饪问答与菜谱展示。

**串起来的关键**：翻车急救的结论回流学习闭环（"这道菜我总是做不好"→ 难度上限
自动下调），跟做过程中的"跳过步骤/中途放弃"同样是难度信号。做，也是输入。

### 环节 4 · 吃（记录/反馈）——数据很好，情感挖掘不足

**已有**：做/剩/太难/餐后心情回流、时光机、月度画册、签到。

1. **剩菜二次创作**：反馈"剩了"不只改推荐，还生成明晚的选择题——"昨晚的红烧肉
   还剩半碗，要不要试试烩饼？"。同一个反馈信号，两个出口。
2. **成就与里程碑**："这是你做的第 100 道菜""可乐鸡翅做了 5 次，换个新做法？"
   ——主动推里程碑事件，画册是其雏形。独居做饭的情感价值被严重低估。

**串起来的关键**：做完一餐 → 冰箱扣减（环节 2 的账本）+ 学习闭环（已有）+
剩菜改造候选 + 里程碑计数。一次「记录」喂四处，正是铁律一的样板。

### 环节 5 · 存（冰箱）——从独立模块到联动引擎

见环节 2/4：临期食材进推荐加分项、采购清单抵扣、做完扣减。
冰箱单页本身**不再加功能**，它的价值全部体现在与其他环节的联动里。

### 环节 6 · 复盘（健康）——有数据没结论

**已有**：营养知识包、画像快照、月报、年度报告。

1. **饮食多样性观察**：不是营养报表，是一句人话——"这周绿叶菜只出现了两次"。
   定位为「观察」而非「建议」，守住不做医疗建议的边界（过敏原记忆的安全设计
   已经验证了这条边界怎么画）。
2. **健康档案联动**（缓做）：体检指标 → 口味调整。合规与免责设计成熟前不启动。

## 四、三个结构性痛点（循环的润滑剂，不是循环的一环）

1. **新用户前 3 天是生死线**。记忆/学习闭环都是「越用越准」型 → 第一天最不准，
   而第一天决定留存。**冷启动画像问卷不是新功能，是记忆系统的初始化**——
   问卷答案直接写入记忆库（来源等级高于 INFERRED，与过敏原同级的安全键）。
   先看数据再动工：对比第 1→3 日流失用户与留存用户的推荐采纳率。

2. **产品侧在盲飞**。后端有告警和健康摘要，但没有产品漏斗：
   推荐展示 → 点开 → 跟做 → 记录 → 反馈。不必上 BI，把「每日关键漏斗」
   并进已有的每日健康摘要（P2-9），一张表指导 80% 的决策。

3. **AI 封图的信任债**。实拍换 AI 图（用户上传成品替换封面 + 小额激励）：
   一举解决信任落差、积累真实内容资产、反哺成就/画册体系。是三个系统的共同燃料。

## 五、排期原则与优先级

排期不按「功能价值」排，按「补环收益」排——优先做能让循环多转一圈的，其次做
让某一环更顺的。

| 优先级 | 事项 | 补环逻辑 |
|---|---|---|
| 先做 | 冷启动画像 + 新手首周 | 给记忆系统初始化，让第一天就"像用了一年的样子" |
| 先做 | 推荐可解释性（理由生成器） | 数据全有只差出口，同时是后续所有解释类能力的地基 |
| 次优 | 冰箱→推荐联动 + 采购抵扣 + 做完扣减 | 一次性建好「库存账本」，三处受益（铁律一样板工程） |
| 次优 | 跟做模式 + 翻车急救 | 竞品难抄的差异化，cooking agent 是现成底座 |
| 缓做 | 剩菜改造、里程碑、浪费追踪 | 依赖用户规模与行为密度，先留数据口子 |
| 缓做 | 实拍换 AI 图 | 需要激励与审核机制，等 DAU 支撑 |
| 观察数据 | 会员权益深化、付费内容 | 先核实 DeepSeek 模型名（P2-4），把免费层价值感知做实 |

## 六、不做清单（明确拒绝，防止功能膨胀）

- ❌ 冰箱单页继续堆功能（扫描、条码、手记账本化）——只做联动，不做独立工具。
- ❌ 社区/UGC 菜谱广场——内容审核成本与当前规模不匹配。
- ❌ 营养/健康「建议」类功能——只做「观察」，永不输出医疗结论。
- ❌ 语音交互、多端（App/Harmony）——厨房语音受小程序限制，多端稀释精力。
- ❌ 一切找不到「主循环挂靠点」的新入口（铁律二）。

---

## 七、怎么衡量「环闭合了」

主循环是否真正转起来，看四个信号（进每日摘要）：

1. **推荐采纳率**：展示 → 做了 的比例（选→做的断层是否在收窄）；
2. **反馈回流率**：做了 → 打开反馈 的比例（吃→记是否顺畅）；
3. **冰箱联动命中数**：推荐理由引用冰箱临期的次数（存→选是否生效）；
4. **次日复访中"有剩余食材/剩菜"场景占比**（存→再选是否自发发生）。

当 1 和 4 持续上升，说明循环已从「工具」变成「引擎」——到那时再谈商业化。
