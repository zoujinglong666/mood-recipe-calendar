# 过敏原大模型归一化设计

## 目标

把用户填写的自然语言忌口和过敏原转换为可确定性匹配的拦截词，并继续由后端硬过滤所有菜谱推荐。

## 范围

- 用户保存饮食偏好时，仅向模型发送忌口与过敏原文本。
- 模型返回 JSON 数组形式的拦截词；服务端校验、去重并保存。
- 推荐时合并原始文本的本地归一化词和模型词，检查菜名、描述、食材与步骤。
- 模型不可用、超时或返回无效内容时，偏好仍保存，使用本地规则作为降级。

## 数据

`user_food_preferences` 新增 `normalized_blocked_terms` TEXT 列，内容为 JSON 字符串，例如：

```json
["虾", "虾仁", "对虾", "大虾"]
```

原始 `avoid_ingredients` 与 `allergens` 保持不变，继续供用户查看和本地降级使用。标准词不对前端暴露。

## 模型边界

复用现有 `LlmClient`，通过结构化 JSON 请求低温度解析。提示词要求只返回用户明确陈述或直接同义的食材/食材类别；不得推断疾病、诊断或提供医疗建议。服务端最多接受 32 个、每个不超过 24 个字符的词。

模型结果只会增加拦截词，永不删除原始输入解析出的词。模型调用失败时返回空模型词，最终过滤仍使用本地词。

## 推荐安全规则

`GuozaiAgent#allowedByPreference` 是基础推荐、深度推荐和周菜单的共享门槛。它合并：

1. 忌口与过敏原的本地归一化词；
2. 已保存的模型标准词；
3. 葱、香菜与辣度等结构化限制。

任一词出现在菜名、描述、食材或步骤中即拒绝该菜。模型不参与推荐时的最终放行决定。

## 验收

- 输入“对虾过敏”会拒绝“虾仁炒蛋”。
- 模型返回的词会保存并参与所有推荐路径。
- 模型失败时，原始文本的本地规则仍然生效。
- 全部后端测试通过。
